Everything is one JSON object. There is no sideband header, no negotiated dialect and no per-peer framing. A bearer may chunk the bytes; it may not change their meaning.

Canonicalisation is the whole game

A signature over "the JSON" is meaningless unless both sides serialise identically. FASP uses RFC 8785 JSON Canonicalization Scheme with the pinned rfc8785 implementation, verified in the test suite against the official RFC test vectors. The signature is computed over the canonical form of the envelope with the signature member removed — never over a reserialisation that might reorder a key.

The JSON decoder is equally deliberate. Duplicate keys, non-finite numbers, oversized integers, invalid UTF-8 and overlarge frames are rejected before dispatch, because a framing quirk that reaches policy is a framing bug in policy.

Signed is not encrypted

The envelope provides authenticity and integrity, not confidentiality. TLS protects the link. A reverse proxy or relay that terminates TLS can read message contents — which is why an end-to-end encrypted relay is listed as something you would have to build, not something this provides.

Discovery stores a card as self-signed and untrusted. Finding a node on a network tells you a key exists and nothing else — no authority is created by scanning. The card is verified against the key that actually signed the envelope, and a card whose key does not match the peer record is an identity-mismatch error, not a silent upgrade.

Two-sided, always. Registration creates a pending relationship. Authority appears only when a human has compared the same fingerprint on both machines.

  1. Fetch or discover the other cardRead the peer's signed profile over HTTPS, or discover it on an explicitly supplied CIDR.
  2. Register in both directionsPOST /pair/hello with their card. The reply supplies a short pair code and this node's own card.
  3. Compare the pair code out of bandOn both trusted local displays, or over a channel you already trust. This is the entire human check.
  4. Approve locally on each nodePOST /pair/confirm with the admin token, peer ID, pair code and the capability prefixes to allow. Pairings expire after 90 days by default.
  5. Only now send workUntil the confirmation step, nothing the peer says can reach an adapter.

Shared Wi-Fi is not shared authority

Being on the same cable, the same WLAN, or a paired Bluetooth link grants nothing. The receiver still checks the signature, the paired identity, the capability, the grant, the expiry, the replay journal and its own policy. Trust-on-first-use applies to a pending record and to nothing else.

Grants narrow, never widen

Pairing prefixes are the base authorization. A grant adds a time-limited requirement on top of it for a specific peer, purpose and window — it can only ever be more restrictive than what pairing already permits.

Reference the grant from an intent.propose payload with grant: {"id": …}. observe and reversible are the executable risk classes; reversible requires a grant. Revoking a grant does not disturb the pairing, and revoking a peer takes effect immediately regardless of pairing state until a fresh pairing is completed.

Read the table again

There is no safety.clear. There is no actuate. There is no kind that turns a peer's text into a local effect. That absence is the protocol's most load-bearing feature, and it is why the layer guard can be a check rather than a convention.

Two planes, two guarantees. The control plane that opens and closes a stream is a reliable packet exchange. The data plane is a sequence of bounded, signed packets under a lease that always expires.

Hard limits. These are constants in the implementation, not configuration.

Reliable or latest

reliable delivery enforces sequence and the credit window: a gap is detected, not silently tolerated. latest is for replaceable samples — telemetry frames where only the newest value matters — and permits drops by design. Both modes use bounded packets and bounded retention, and both require an explicit expiry.

Packetisation

Large frames are split into chunks as needed rather than by building a list of all chunks first, which keeps peak memory proportional to the chunk in hand instead of the whole message. Reassembly permits at most eight incomplete frames per consumer by default, so a slow or absent reader cannot pin memory indefinitely. Packets carry a checksum and are validated before they are stored or forwarded.

Forwarding signs again

A forwarded event is signed by the forwarding node, not re-presented as the original sender's. The receiving node re-checks peer state, capability, current sharing policy, grant expiry and revocation before every live push, and removes a stale subscription without blocking the producer's packets.

Worked examples from the test suite

Stream sharing with an empty rule set denies remote streams. A grant can only narrow a pairing prefix. Reusing an idempotency_key with a different payload is refused rather than replayed. Replaying an envelope returns the original recorded response. Each of these is a test, not a paragraph.
