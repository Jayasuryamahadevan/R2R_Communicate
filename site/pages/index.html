Coordination that refuses to become control.

FASP is a signed-envelope layer for coordinating agents, robots and edge devices. Each node keeps its own identity, its own policy and its own authority — and an enforced boundary keeps every peer above hard real-time safety.

One checked property, not a promise in a README.

      

      
A coordination protocol and a control system are different products. Conflating them means a network fault degrades throughput in one and degrades safety in the other. FASP draws the line at a layer boundary that the running process enforces — layers.py refuses an adapter at startup if it declares something whose meaning is a safety function, whatever layer it claims.

Hard real-time local safety

          
E-stop, safety-rated protective fields, speed and force limiting, the safety PLC, motor control. Runs on certified hardware or an RTOS, outside this process.

Rule 1 · declared layer

        
There is no actuation verb.

        
ACTUATE appears in no permitted set for any layer. A peer can ask for a goal, a halt, or an observation. It cannot ask for an action, because the word does not exist on the wire.

      

      

        
Rule 2 · deny list

        
Meaning is checked, not names.

        
A declaration is exactly what a mistake gets wrong, so capabilities whose meaning is a Layer 1 function are refused whatever layer they declare — estop.clear, safety.zone.mute, brake.release, motor.setpoint.

      

      

        
Rule 3 · one-way halt

        
Halt is one-way.

        
There is no safety.clear envelope kind. safety.halt can be requested over a network; clearing it is local, physical work at the machine.

The node is the trust boundary. Not the container.

      

      
A container is one convenient way to package a node. A host process or a device gateway runs the same package. Give every independently trusted system its own identity and its own persistent state directory, and never copy one node's state volume onto another.

    


    

      

        
Identity

        
An Ed25519 keypair and a signed profile

        
A stable system_id derived from the public key, an ID card published at /.well-known/fasp/id-card.json, and the endpoints a peer needs to reach you. Private key and admin token live at mode 0600 in the node's state directory.

      

      

        
Policy

        
Default-deny, decided here

        
Pairing establishes capability prefixes. Grants narrow them further for a time window. Both are enforced locally on every request — no central proxy is consulted, and a future issuer cannot override a node's own deny.

      

      

        
State

        
One SQLite file, one work lifecycle

        
queued → running → succeeded | failed | cancelled shared by capability work and fleet missions, with idempotency, a replay journal and a hash-chained audit log that you can verify end to end.

      

      

        
Adapters

        
Local, declared, bounded

        
An adapter is a local object with a capability list and a handler. It runs beside its device, never as a remote effect. The default agent adapter deliberately does something small — connect real machinery through a reviewed adapter.

Seven gates, all before your adapter.

      

      
A failure at any stage is persisted, so resubmitting the same idempotency_key returns the identical recorded outcome instead of running the checks — and the effect — a second time.

Receipts and results are different things

      
intent.propose never claims a model understood or completed the requested work. Delivery of the request and the result of the work are separate records, so a lost receipt never reads as a success.

Every input ends up as one of three forms.

      

      
Adapters differ. The contract does not. A source adapter authenticates, parses, validates and attaches provenance, then enters the same signed path — which means authorization, framing and storage are written once instead of once per protocol.

    


    

      

        
01 / event

        
Packet

        
One request, event, receipt or small result, wrapped in a single signed envelope of at most 64 KiB. The kind field selects its schema and its handler.

        
task request → receipt

      

      

        
02 / continuous

        
Stream

        
A finite lease opens a sequence of signed, bounded packets. Choose reliable delivery or latest-sample semantics per stream; the receiver enforces rate, window and retention.

        
telemetry → dashboard

      

      

        
03 / one time

        
Artifact

        
An immutable result stored by digest locally, then referenced from a packet when an authorized node needs to fetch it. Keeps large payloads out of the envelope budget.

        
report → digest reference

      

    


    

      
A stream is never an unlimited right to keep sensing

      
Every lease has an explicit expiry and bounded retention. Revocation stops future delivery — it cannot recall data already delivered, which is why the consent model is checked before each push rather than once at open.

Useful where systems must agree across a boundary.

      
FASP is most useful when two separately operated nodes need signed requests, local authorization and a durable record. Each example below uses the same packet, stream and artifact forms; the link and local adapter change with the site.

    


    

      

        
Laptop ↔ Pi

        
Two agents, one accountable request

        
An MCP host asks a local FASP node to contact a paired peer. The request is signed, queued before delivery and reported as sent or pending. The receiving agent keeps its own capability policy.

        
MCP stdio → HTTPS or Bluetooth packet

      

      

        
Device ↔ gateway

        
Intermittent edge telemetry

        
A Pi or gateway forwards bounded observations as a leased stream and stores a larger immutable result by digest. A network outage delays delivery; it does not grant new authority or extend an expired lease.

        
Stream → optional artifact

      

      

        
Robot ↔ fleet service

        
Coordinate goals, leave safety local

        
Container or host nodes exchange task and reservation packets. A local adapter may accept a goal, while motor control and the certified safety path stay on the robot.

        
Signed packets → reviewed local adapter

Built and tested

        
Enforcement, durability, observability

        
Ed25519 identity with RFC 8785 canonicalisation verified against the official vectors · capability-scoped pairing and revocable grants · a durable work lifecycle with idempotency · SQLite in WAL mode with versioned migrations · a hash-chained audit log · two-layer token-bucket rate limiting · mutual TLS · Prometheus metrics · optional MCP stdio tools.

      

      

        
Deliberately absent

        
Stated, not implied

        
Hard real-time — hard_realtime is the constant False with reasons, not a computed value. Safety certification — Layer 1 authority belongs to certified hardware. Independent validation — the safety case marks it undeveloped rather than omitting it. End-to-end encryption — the signed JSON envelope is not encrypted, only signed.
