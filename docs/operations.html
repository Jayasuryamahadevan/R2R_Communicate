Running it without lying about it

01

Three things it cannot do, stated structurally rather than hedged. A capability you cannot state plainly is a capability a deployment team will discover late.

Not hard real-time

The GIL is the reason

CPython holds a global lock, its cyclic GC can stop all threads for an unbounded time, and allocation has no bounded worst case. hard_realtime is the constant False — not a value computed from a benchmark that happened to pass today.

Not safety certified

Layer 1 lives elsewhere

Authority at Layer 1 belongs to certified hardware outside this process. safety.halt can only ever be requested over a network; clearing a halt is local, physical work at the machine.

Not validated

Marked undeveloped

The safety case records this claim as undeveloped rather than omitting it, and its certifiable verdict is False. A research artifact that hides its gaps is worse than one that lists them.

Covered by this build

TLS 1.3 with optional mutual TLS · RFC 8785 canonicalisation verified against the official test vectors · application-layer rate limiting in two layers · a durable hash-chained audit trail · grant-based revocation · constant-time admin-token comparison · structured JSON logs with secret redaction · a CycloneDX SBOM.

Still your responsibility for a real deployment

An RFC 8785 implementation in every other language your peers speak · hardware-backed keys where the platform offers them · a real external authorization issuer · encrypted artifact storage at rest · rate limiting and a WAF at a reverse proxy in front of this one · and local safety controllers and emergency stops for every physical actuator.

No example deployment is approved for physical actuation

Before attaching a device, test certificate rotation, revocation, source restrictions and denied requests. A working handshake is not an acceptance test.

02

These are guards in code, not a third-party audit attestation. Ten behaviours the hardened build actually performs, and what each one prevents.

  1. 01Pairing-bound signaturesEd25519 scoped to a confirmed peer, with local grants and revocation beneath it.
  2. 02Startup and dispatch checksCapabilities validated at adapter startup and on every dispatch. A remote payload cannot downgrade the adapter's authoritative risk class.
  3. 03Idempotency identityScoped to the original peer and the original payload, so a reused key with different content is refused rather than replayed.
  4. 04Response replay bindingTied to the exact authenticated signed envelope, so a forged retry cannot collect another peer's recorded answer.
  5. 05Artifact authorizationPer-peer authorization for retrieval, with digest validation.
  6. 06Two-layer rate limitingPer-IP before authentication, per-peer after, with limited HTTP and WebSocket message sizes.
  7. 07Posture against realityStartup checks the actual listener TLS and mTLS settings, not the advertised URL. The configured profile is retained.
  8. 08Audit integrity firstThe audit chain is verified against the opened database before any loop or socket starts. Corrupted storage refuses hardened startup.
  9. 09Outbox recoverySingle-owner restart recovery, with retries bounded by signed message expiry, dead letters and durable per-destination ordering.
  10. 10Online backup APIA WAL-aware snapshot backup for database contents, rather than a file copy that races the write-ahead log.

03

Three profiles, and the default refuses the wrong thing. The profile is evaluated and enforced before anything binds a socket.

ProfileUse it forWhat it insists on
developmentLocal inspection, loopback onlyHTTP may be opted into explicitly; wildcard and loopback advertisement is refused
hardenedA controlled LAN before real devicesTLS present, explicit public URL, audit chain verified, rate limits bounded
productionAny exposed or physical deploymentAll of the above, plus mTLS and a stable identity configuration
run a node the way production expects
python -m fasp_harness serve \
  --config /etc/fasp/node.json \
  --host 0.0.0.0 --port 8766 \
  --public-url https://node.example.internal:8766 \
  --state-dir /var/lib/fasp \
  --tls-cert /run/secrets/tls.crt \
  --tls-key /run/secrets/tls.key \
  --tls-client-ca /run/secrets/mesh-ca.crt \
  --security-profile production

The profile validates configuration choices. It does not validate vendor certification, encrypted-disk status, or real hardware behaviour. Do not use the deliberately insecure HTTP development switch on an exposed interface.

Operator commands worth knowing

Each answers a question someone actually asks during a deployment, and every one accepts --json.

the questions, and the command that answers each
python -m fasp_harness layers          # the layer model this build enforces
python -m fasp_harness rt-probe        # what timing can this host honestly offer?
python -m fasp_harness hil             # run the safety response-time scenarios
python -m fasp_harness zones           # the IEC 62443-3-2 zone/conduit model
python -m fasp_harness sbom            # CycloneDX bill of materials
python -m fasp_harness safety-case     --config examples/node.json
python -m fasp_harness security-report --config examples/node.json
python -m fasp_harness posture         --profile production --host 0.0.0.0
python -m fasp_harness guard-budget    --round-trip-ms 40 --speed-limit-mps 2 --clearance-m 3

These exit non-zero on a failing verdict

safety-case, security-report, posture, hil and guard-budget are pipeline gates, not reports nobody reads. That is why they are commands and not documentation.

04

The reference deployment is deliberately unfriendly. Non-root UID 10001, read-only root filesystem, all Linux capabilities dropped, no-new-privileges, and a port bound to host loopback for an upstream restricted ingress.

Before you start it

  1. Copy deploy/production/.env.example to .env and set FASP_NODE_NAME and FASP_PUBLIC_URL. The URL must resolve for peers, and its DNS name must appear in the certificate's subject alternative names. fasp-init refuses a silent configuration change against a persisted identity.
  2. Create deploy/production/secrets/ outside version control: tls.crt / tls.key for the server, client.crt / client.key for outbound mTLS, and mesh-ca.crt for trusted nodes. UID 10001 must be able to traverse the directory. The client certificate needs client authentication use; the server certificate needs server authentication use.
  3. Validate, build, start — and read the result.
deploy the compose stack
cd deploy/production
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps

# fasp-init should exit 0, fasp should become healthy,
# fasp-drain should stay running. If not:
docker compose logs fasp fasp-drain

Three services share one state volume: fasp-init creates the durable identity, fasp serves the HTTPS listener, and fasp-drain runs a supervised fasp drain --watch loop against the same directory. The drain process retries only the CLI's signed outbox, within each envelope's roughly two-minute expiry. Inspect dead letters with fasp outbox.

The image installs hash-checked runtime packages from requirements-prod.txt, exported from uv.lock. Regenerate it whenever the lockfile changes; CI checks that it is in sync.

05

Use the online backup interface. Copying fasp.db while the write-ahead log is live gives you a torn snapshot that looks like a complete one.

State lives in one SQLite database in WAL mode, plus the identity key, the admin token and two JSON side files. Preserve the entire state directory through routine updates — the identity is what makes the node recognisable, and regenerating it changes its system_id.

  • Snapshot online through the provided API, which understands the WAL, rather than by copying the file.
  • Restore into a stopped node. Starting two writers over one volume is a split brain with a schema.
  • Verify the audit chain after restore. A hardened node checks it at startup and refuses to run if it fails — that is the intended behaviour, not an outage to work around.
  • Test the restore before you need it. A backup that has never been restored is a hypothesis.

Adapters need a sandbox, not a timeout

The in-process Python worker timeout bounds how long the harness waits; it does not terminate a thread that is already stuck. For stateless adapters, --process-adapter starts a killable subprocess per execution, treating its stdout as a bounded JSON protocol and never returning child stderr to a peer.

Use it only for independently replayable, stateless work — not for device adapters that own persistent hardware sessions. Process separation alone does not remove inherited environment variables, restrict filesystem access or block network access; configure those with separate service accounts, runtime restrictions, network policies and cgroups. No remote model text should choose the local adapter import path.

Release blockers with no code-only shortcut

Independent security audit · real-hardware safety assessment · multi-host endurance testing · supervised out-of-process adapters · site-proven drain behaviour across partitions · production-grade cross-NAT transport if that topology is required.

06

Three probes, because "is it up" is three different questions. Conflating them is how a standby ends up accepting work it should refuse.

ProbeQuestionAction on failure
/livezIs this process wedged?Restart it
/readyzShould this node receive work?A standby correctly answers no — remove it from load balancing
/health/detailWhich check is failing?Admin token; inspect per-check detail

/metrics exposes Prometheus text. Alert on audit-chain failure, readiness flapping, queue depth, dead letters, stale safety observations, vendor status and failed authorisations — and export durable security events off-node, because an audit trail the attacker can delete is a log.

fasp_harness/observability/ · structured logs with secret redaction are on by default

07

The checklist a deployment should actually be signed off against. Grouped by who owns the work, because these belong to different disciplines.

Before design freeze

Threat model and SLOs

Record data sensitivity, identity lifetimes, dangerous capabilities, operators, vendors and trust boundaries. Specify measured p50/p95/p99 latency, maximum task age, recovery-time target, backup frequency, disk limits and maximum clock uncertainty.

Before deployment

Fault injection

Terminate the node at each state transition. Simulate partitions, duplicates, reordering, corrupted messages, a full disk, clock drift, certificate expiry and concurrent conflicting requests.

Before exposure

Security

Fuzz signed envelopes, configuration and packet validators. Test untrusted peers, replay and grants. Rotate keys and review logging for secret exposure. Scan dependencies and sign release artifacts.

Before devices

Observability and sandboxing

Protected Prometheus scrape and alerts. Put adapters behind OS resource limits, allowlisted outbound network, filesystem isolation and a supervisor that can terminate hung jobs.

Before motion

Robotics

Physically verify independent E-stop, brake, protective fields, safe speed, local autonomy and hazard analysis. Validate ROS 2 security enclaves if ROS 2 is enabled. Simulation-only evidence is not hardware certification.

Before release

Release

Pin exact artifact digests, test built-wheel installation, restore backups, evaluate mixed-version compatibility, commission an independent security review — and require an operator's written, site-specific go/no-go.

What CI already runs on every push

A matrix across Python 3.11 to 3.13: lockfile-drift check, ruff lint over the package and tests, the full unittest discovery suite, a wheel build installed into a clean environment with hash checking, and a container build and run. CLI-driven gates then assert the layer model, the hardware-in-the-loop scenarios, the IEC 62443 zone model, the SBOM, and the safety case — with the safety-case gate asserting that the set of unsupported claims is exactly the known one, so a new gap cannot be introduced quietly.

That last part is the point

A gate that fails when the failure list grows is worth more than a report that describes the failures after they ship. The same reasoning is why this documentation states its own limits up front.
