From empty directory to two paired nodes

Everything needed to install, run, pair, extend and debug a FASP node, in the order you will need it. Wire-level schemas and edge cases stay in the repository specifications; this page is the working path through them.

01

Requirements. Python 3.11 or newer, Git, and uv — though uv is only the fast option. Any PEP 517 installer works, because the package has no unusual build requirements.

clone and create the environment
git clone https://github.com/Jayasuryamahadevan/R2R_Communicate.git
cd R2R_Communicate
uv sync --python 3.11 --locked --extra test --extra dev
source .venv/bin/activate

# prove the build is sound before trusting it
ruff check fasp_harness tests
python3 -m unittest discover -s tests -v

The lint and test commands are not optional decoration — they are exactly what CI runs, on every push, across 3.11 to 3.13. Running them locally first turns a confusing CI failure into a clear one.

Runtime dependencies are cryptography, starlette, uvicorn, rfc8785 and websockets. Five wheels on an audited edge appliance is a short list, which is the point.

02

One node, loopback, no peers. Get this working first. It is the fastest way to find out whether your Python, your state directory and your ports are fine before they are entangled with someone else's machine.

local quick start
fasp init --name my-node --state-dir .fasp/my-node

fasp serve --name my-node --state-dir .fasp/my-node \
  --host 127.0.0.1 --port 8766 --insecure-http

The server prints its system ID, the URL of its public profile, and the path to its private admin token. Keep that admin token and the identity private key to yourself. Never commit them, never bake them into an image, and never copy one node's state directory onto another node.

check that it is alive, then look at what it claims to be
curl -s http://127.0.0.1:8766/health
curl -s http://127.0.0.1:8766/.well-known/fasp/id-card.json | python3 -m json.tool
curl -s http://127.0.0.1:8766/openapi.json | head -40

Wildcards need a real advertised address

When you bind 0.0.0.0 or ::, you must supply --public-url with the address peers will actually use. The server refuses to advertise a wildcard or loopback address — because an ID card pointing at 0.0.0.0 is a card that cannot be used.

Where state lives

Everything durable is under the state directory: the identity key and admin token at mode 0600, fasp.db with all pairing, work, stream and audit state, and the local artifact store. Point --state-dir somewhere persistent and backed up — an ephemeral directory means a new identity on every restart.

03

Two machines, two identities, two state directories. Run a second instance on a phone, a Pi or another host with its own state folder and its own reachable URL, then pair them.

the second node
python3 -m fasp_harness serve \
  --host 0.0.0.0 --port 8766 \
  --public-url http://192.168.0.22:8766 \
  --name laptop-agent --state-dir .fasp/laptop --insecure-http

Its advertised URL must be the address the other node can reach. If it is not, pairing fails with a connection error rather than a policy error, which is at least a legible failure.

04

The human check is the whole of it. Everything else in the trust model is machinery protecting a fingerprint that a person has already compared.

  1. Read the other cardFetch its /.well-known/fasp/id-card.json, or discover it with fasp discover on a CIDR you administer.
  2. Register, in both directionsfasp register --peer http://192.168.0.22:8766 on A, and the equivalent on B. This creates a pending relationship and returns a pair code. It grants nothing.
  3. Compare the same code on both machinesOn both trusted local displays, or over a channel you already trust. If the codes differ, stop here.
  4. Approve locally, on each nodefasp approve with the peer ID, pair code, and only the capability prefixes you actually intend to allow — for example observe. and coordinate.
  5. Confirm the relationshipfasp peers shows the pairing, its scope and its expiry. It lasts 90 days by default; re-pair deliberately.
over a radio bearer, repeat on both nodes
fasp radio-register --state-dir ~/.fasp-agent \
  --peer http://127.0.0.1:8766 --mode classic --channel 8

# or BLE on Python 3.14+; pick the address type BlueZ reports
fasp radio-register --state-dir ~/.fasp-agent \
  --peer http://127.0.0.1:8766 \
  --mode ble --psm 0x0080 --address-type random

If a key is ever suspected compromised

Call /pair/revoke (or fasp approve with a revocation). The peer is rejected immediately regardless of any prior pairing state, until a fresh /pair/hello and /pair/confirm are completed.

05

A request is a payload inside a signed envelope. The payload is the part you write; the envelope around it is what the harness produces and verifies.

the payload of an intent.propose
{
  "intent_id": "status-001",
  "idempotency_key": "laptop-status-001",
  "capability": "observe.system.status.v1",
  "objective": "Return a non-sensitive service health summary.",
  "constraints": { "network": "none", "retain": "none" },
  "risk": "observe"
}

Three fields carry most of the weight. capability must exist in both the pairing scope and the receiving adapter's registered list. idempotency_key is what makes a retry safe, and it is scoped to this peer and this exact payload — reusing it with different content is refused rather than replayed. risk selects the risk class; reversible requires a live grant.

send it through the durable outbox
fasp communicate --state-dir ~/.fasp-agent \
  --peer http://192.168.0.22:8766 \
  --capability observe.system.status.v1 \
  --objective "Return a non-sensitive service health summary."

fasp task-status --state-dir ~/.fasp-agent --id status-001
fasp drain --watch          # supervised retry loop against the same state
fasp outbox                 # inspect what is queued, and any dead letters

fasp communicate and fasp drain persist and retry. They cannot extend the original roughly two-minute envelope expiry, and they cannot guarantee exactly-once external device effects — retrying is safe, external side effects are your adapter's responsibility to make idempotent.

06

An adapter is a local object with declared capabilities. This is the only place in the system where peer-requested work becomes an effect, which is why it is the only place worth being careful.

the entire required interface
class MyAdapter:
    def capabilities(self) -> list[dict]:
        # declare name, risk class and bounded runtime
        ...

    def handle(self, intent: dict) -> dict:
        # return bounded output, nothing else
        ...

    def cancel(self, idempotency_key: str) -> bool:
        # optional
        ...

Start from fasp_harness/example_adapter.py, then load it from a local import path:

load an adapter, optionally out of process
# in-process
python3 -m fasp_harness serve --adapter my_package.adapter:create_adapter

# killable subprocess per execution — stateless adapters only
python3 -m fasp_harness serve \
  --adapter my_package.adapter:create_adapter --process-adapter

What an adapter must not do

It must not treat peer text as permission for shell commands, network calls, account changes, destructive actions, continuous sensing, or physical actuation. Those need separately declared capabilities and local approval gates — and physical actuation needs a safety controller, not a Python handler.

Declare a capability whose meaning is a safety function and startup fails

The layer guard reads the meaning of the name, not the layer it claims. estop.clear, safety.zone.mute, brake.release and motor.setpoint are refused at startup. That refusal is the design working, not a bug to work around with a different name.

07

If it is continuous, it is a lease. Send telemetry or media through a stream, not as a series of individual packets — and always send the control that closes it as a reliable packet.

  1. The sender's operator allows the stream in its stream_sharing rules, naming the receiving peer, purpose, fields and limits. An empty list denies remote streams.
  2. The sender opens a lease with stream.open, stating purpose, fields, delivery mode, rate, duration and size bounds.
  3. The receiver's operator allows it too — on their node. Both sides consent; neither can be assumed.
  4. Packets flow as stream.packet, signed and sequenced, within every declared bound.
  5. The sender closes with stream.close. Expiry also closes it, because a lease that only ends politely is not a bound.

For JSON, every packet must be one complete UTF-8 object with no duplicate keys and no non-finite numbers, and top-level keys outside the declared fields are rejected before storage or forwarding. The core does not recursively filter nested values and cannot inspect bytes inside binary content — so validate nested structures in your adapter and serialise only approved content.

08

Most failures name their own cause. This is the mapping from what you will see to what is actually wrong.

SymptomMost likely causeCheck
auth.* on every requestClock skew, or an expired pairingCompare issued and expires times on both hosts; check fasp peers for expiry
Signature fails, keys look rightCanonical JSON differs between implementationsBoth peers must use RFC 8785 exactly — never sort_keys=True as a substitute
capability.unavailableNo local adapter declares itThe adapter's capabilities(), not just the pairing scope
auth.invalid_grantGrant expired, or does not name this purposeGrant subject peer, capability prefixes and remaining duration
Stream refused immediatelyEmpty or non-matching stream_sharing ruleBoth nodes' rules; the exact peer ID, purpose and fields
resource.too_largePayload past the envelope budgetUse a stream, or store an artifact and send its digest
resource.exhaustedRate limit or queue depthPer-peer and per-IP token buckets; the declared max_runtime_s
Node restarts refuse to startAudit chain failed verificationIntended behaviour after a tampered or partial restore — investigate before overriding
Wildcard bind refuses to serveNo usable --public-urlSupply the address peers actually reach; loopback and wildcard are refused
Nothing arrives, no errorPush is an optimisation; nothing was polledPull task.status or inbox.pull — durable state is the source of truth
