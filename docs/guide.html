01 / CONCEPT

What FASP is

FASP is a coordination protocol proposal and runnable Python reference harness for independent autonomous systems. A node has its own cryptographic identity, local policy, durable work state, and local adapters. Peers can request work and exchange data, but the receiving node decides whether a specific capability is allowed.

The core rule

A network message cannot act as an emergency stop reset, motor command, or other local safety function. The harness coordinates goals; the machine keeps physical authority.

The default agent adapter is deliberately simple: it echoes a requested objective. Connect a real agent or device through a reviewed local adapter with declared capabilities.

02 / INSTALL

Run a node

You need Python 3.11 or newer. Clone the source and create a local environment. This local example binds to loopback for inspection:

git clone https://github.com/Jayasuryamahadevan/R2R_Communicate.git
cd R2R_Communicate
uv sync --python 3.11 --locked
source .venv/bin/activate
fasp init --name my-node --state-dir .fasp/my-node
fasp serve --name my-node --state-dir .fasp/my-node \
  --host 127.0.0.1 --port 8766 --insecure-http

Each independent node needs its own state directory. Its identity key, pairing records, replay journal, outbox, work state, and artifacts live there. Do not copy one node’s private state to another.

For a reachable peer deployment, configure the host, public URL, TLS certificates, and persistent storage as described in the two-node CLI guide ↗.

03 / TRUST

Pair two systems

  1. Run both nodes.Each advertises a signed public identity card at its reachable endpoint.
  2. Register in both directions.Use fasp register for HTTPS or fasp radio-register for Bluetooth.
  3. Compare the fingerprint out of band.Registration creates a pending relationship, not permission.
  4. Approve locally on both nodes.Use the exact peer ID, pairing code, and only the capability scopes needed.

Being on the same cable, Wi-Fi network, or paired Bluetooth link does not authorize FASP work. The receiver still checks the envelope signature, paired identity, capability, grant, expiry, replay state, and local policy.

04 / DATA MODEL

Packets, streams, and artifacts

FormUseBoundary
PacketOne event, request, receipt, or small resultSigned envelope, up to 64 KiB
StreamRepeated telemetry or media blocksFinite lease, bounded packets, rate, window, and retention
ArtifactLarge one-time resultLocal immutable storage, digest and authorized fetch

A stream opens through signed control, then carries signed stream.packet envelopes. reliable delivery enforces sequence and credit; latest allows replaceable samples to be dropped. A stream is never an unlimited right to keep sensing.

Source adapters validate device or broker data before it enters this model. If a device cannot sign for itself, a gateway signs with its own identity and preserves the source as provenance.

05 / CONNECTIVITY

Choose a link

On an IP network, use HTTPS for request and response or WebSocket for bidirectional push. Ethernet, Wi-Fi, and cellular connectivity are supplied by the operating system; FASP uses the reachable IP endpoint. The REST interface exposes /openapi.json and accepts paired, signed requests at /fasp/v1/envelopes.

On Linux, Bluetooth Classic RFCOMM and BLE L2CAP credit based channels can carry the same signed protocol. BLE needs Python 3.14+ and compatible BlueZ support. These radio bearers are opt-in and require OS pairing as well as FASP pairing.

MQTT, ROS 2, DDS, serial, CAN, GATT, OPC UA, and similar systems need a bridge or source adapter. The communication catalog ↗ distinguishes implemented bearers from IP carriers and adapter plans.

06 / OPERATIONS

Boundaries and production

  • Use TLS 1.3 on routable IP links; mTLS is available for transport identity.
  • Keep identity keys, admin tokens, and state directories private and persistent.
  • Declare capabilities in local adapters and keep physical safety controllers outside the process.
  • Set stream sharing rules explicitly; an empty rule set denies remote streams.
  • Measure latency, loss, resource use, and recovery on the actual link before setting service targets.

This is a security-focused reference harness. It is not independently certified safety software. Production use needs deployment-specific security controls, local safety assurance, and the gates in production readiness ↗.
