02 / Architecture

How the system is actually put together

A node-first mesh. Each node owns its identity, its policy, its durable work state and the adapters it is allowed to call. The interesting decisions are all about where the boundaries sit — this page is about those boundaries, and what enforces each one.

01

The short version. Nodes connect directly, each enforcing its own policy at its own edge. There is no control plane in the middle, because a middle that can grant authority is a middle that can be wrong about it. Routing is added later, and only when reachability demands it.

Why node-first

The infrastructure ideas here come from Google's Agent Mesh: keep node, control and networking roles small, place enforcement at each node, and add routing only when the deployment topology requires it. FASP keeps its own Python implementation, its own signed-envelope protocol and its own device safety model. There is no protocol compatibility claim and no reused code.

The practical consequence is that the deployment unit is a trust boundary, not a process count. Run one node per independently trusted system first. Split the control function or add a router later, and only to meet an operational ownership or reachability requirement.

Never copy one node's state onto another

A SQLite file moved between hosts is not replicated high availability, it is two writers with one identity key. Give every node its own identity and state directory, and never bake a private identity key into an image.

02

What one node owns. A stable cryptographic identity, a local authorization policy, durable work and stream state, and the adapters it may call. Nothing else. An operator approves peers here, not at a central proxy.

Identity

A keypair that survives restarts

Ed25519, stored at 0600 in the state directory. The system_id is derived from the public key, not assigned, so it cannot be claimed by configuration. The signed ID card at /.well-known/fasp/id-card.json advertises endpoints, capabilities, layers and a runtime profile.

fasp_harness/crypto/

Policy

Default-deny, in two layers

Pairing establishes capability prefixes with a 90-day validity. Grants narrow those prefixes further for a named purpose and duration. Scope matching is a dot-segment prefix match, so observe. cannot reach reversible.deploy by accident.

fasp_harness/policy/

Durable state

One database, versioned

SQLite in WAL mode at fasp.db, schema tracked through PRAGMA user_version across eleven numbered migrations. Peers, inbox, work items, grants, revocations, streams, reservations, missions, leases, twin observations and a hash-chained audit log all live here.

fasp_harness/storage/ · artifacts/

Adapters

The only place code runs

An adapter declares its capabilities, handles an intent, and optionally accepts a cancel. Capabilities are validated at startup and at every dispatch, and a remote payload can never downgrade an adapter's authoritative risk class. Process-supervised mode is available for stateless adapters.

fasp_harness/adapter_worker.py · example_adapter.py

One dispatcher, three bearers

HTTP, WebSocket and Bluetooth do not each get their own validation path. There is one bounded JSON decoder and one envelope dispatcher; the bearer only decides how bytes arrive. Duplicate JSON keys, non-finite values, oversized integers, invalid UTF-8 and overlarge frames are rejected before dispatch, so a framing quirk cannot become a semantic one.

03

Order matters. Signature, then peer, then capability, then grant, then layer, then replay, then dispatch. Each gate can only reject; none of them can widen what a later one allows.

  1. 01Ed25519 over canonical JSONThe signature covers RFC 8785 canonical JSON of the envelope with the signature member removed. Canonicalisation is the pinned rfc8785 implementation, checked against the official test vectors — not a hand-rolled json.dumps(sort_keys=True).
  2. 02Audience, expiry, nonceto must match this node. expires_at is enforced against the declared clock-skew allowance. The nonce is recorded. Any failure here is an auth.* error mapped to 401.
  3. 03Paired, not revokedThe signing key must match the key recorded for that peer. A revoked peer is refused regardless of pairing state until a fresh /pair/hello and /pair/confirm. Self-pairing and expired pairing records are refused.
  4. 04Capability prefixDot-segment prefix match against the pairing scope, and against what the adapter actually registered. An unmapped capability returns capability.unavailable rather than being coerced into the nearest one.
  5. 05Grant, when requiredReversible-risk capabilities require a live grant naming this peer, capability and purpose. observe and reversible are the executable risk classes; a grant can only narrow, never widen.
  6. 06Layer guardThe interaction must be permitted toward the declared layer, and no capability name may match the semantic deny list. This is the gate that makes the invariant structural rather than cultural.
  7. 07Replay and journalOne message_id dedup gate shared by every kind. A retried envelope returns its original recorded response — never a second execution of the same effect.

Idempotency is identity, not a flag

An idempotency_key is scoped to the original peer and the original payload. The same key with a different payload is not a replay — it is a different request and is refused. Response replay is tied to the exact authenticated signed envelope, so a forged retry cannot collect another peer's recorded answer.

Bounded execution

Dispatch runs on a bounded worker pool with a real wall-clock timeout taken from the capability's declared max_runtime_s. Past that, the caller receives task.progress immediately and either polls task.status or — over /fasp/v1/channel — is pushed the eventual result. A Python thread timeout does not kill a stuck thread, which is why process-supervised adapters exist for stateless work.

A receipt is not a result

intent.propose never asserts that a model understood or completed the requested work. The delivery receipt and the task result are distinct records, so a lost receipt can never be read as a silent success.

04

One lifecycle. Capability work and fleet missions share identity, idempotency, state transitions and recovery. A mission's progress lives in a phase field, not in a second state machine.

Failure that fails safely

A stale intent lease fails safely after a restart instead of replaying a possibly completed effect. Outbox recovery is for a single-owner restarted node, with retries bounded by the signed message expiry, per-destination ordering, and dead letters you can inspect. Recovery across a partition, with a second writer, needs a state and consensus design that does not exist yet — so it is not claimed.

Do not run two writers on one state volume

A central active-active control plane would need a separately designed state and consensus architecture. Running multiple writer replicas over a shared SQLite volume is not high availability — it is a split brain with a schema.

05

A stream is a lease, not a pipe. Finite duration, bounded packets, bounded retention. The receiver accepts one only when the sender's scope, the grant and the node's own sharing rule all agree — and forwarding stops the moment the downstream recipient's consent changes.

Four checks must agree

  1. The sender is a paired peer whose capability scope covers the exact stream capability.
  2. The grant is valid for that peer, capability and stated purpose, when a grant is required.
  3. The node's own stream_sharing rule names that peer and allows the purpose, fields, media type, delivery mode, rate, duration, packet size, window, retention and any forwarding recipients.
  4. The lease is live and every packet stays inside the accepted size, sequence, rate and checksum bounds. JSON records also pass the top-level field allowlist before being stored or forwarded.

An empty stream_sharing list denies remote streams. Forwarding is off unless both the local rule and the stream contract name the exact downstream peer, and that peer is itself paired, authorised and presenting a recipient grant. The forwarding node rechecks peer state, capability, current policy, grant expiry and revocation before every live push; a stale subscription is removed without blocking the producer.

What the field allowlist does not do

For application/json, every packet must be one complete UTF-8 object with no duplicate keys and no non-finite numbers. The core rejects top-level keys outside the declared fields before storing or forwarding. It does not recursively filter nested values, and it cannot inspect bytes inside image, audio or other binary content. A fields declaration is a contract, never proof that opaque bytes were inspected or redacted.

06

Start with one node per trusted system. Add network infrastructure only when reachability or ownership actually requires it. Most deployments never need more.

01 / local

Single host

One process owns identity, state, policy and the adapters sitting beside its device or agent. No network exposure required.

Best for development and edge devices

02 / direct

Peer mesh

Nodes connect directly over HTTPS, WebSocket, or the Bluetooth bearers. Each peer holds a signed card and a pairing record.

The current network model

03 / adapted

Edge gateway

A local gateway validates constrained device data and signs it with its own identity, preserving the original source as provenance.

For fieldbuses and non-FASP devices

Packaging is not a boundary

The same Python package runs as a process or in the included Docker image. A container is one convenient way to package a node; a host process or a device gateway runs the same package. A deployment supplies its endpoint, TLS material, persistent state volume and adapter configuration. Devices that cannot run the package connect through a FASP gateway on their own host — keep hardware drivers beside the hardware, and keep safety interlocks local.

NodeConfig.from_file() rejects unknown keys, so a misspelled safety or stream-sharing setting fails loudly instead of silently falling back to a default. Absent configuration produces an absent subsystem, never a simulated one standing in quietly.

What is not implemented yet

A relay for unreachable peers, QUIC, MQTT/DDS bridges, remote identity issuance, automatic enrolment and end-to-end encrypted relaying are extension points, not runtime features. The included mesh module is a network simulator, and the outbox is a durable queue without a production network drain worker.

Do not split modules into services because they have different names

Run one node per trust boundary first, then separate the control function or add a router only to meet an operational requirement. A module boundary is not automatically a network boundary, and a network boundary you did not need is one more thing to secure.
